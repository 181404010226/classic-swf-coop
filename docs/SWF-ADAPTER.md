# SWF 改为两端本地联机：这次的做法

## 先确定规则由谁运行

旧版在房主运行 SWF，再把编码画面传给搭档。新版每台设备自己加载同一 SWF，网络只确定「第几帧，两名玩家分别按了什么」。渲染、碰撞、机关仍由原版 Box2D 执行。

适配接口：`lanInit`、`lanMenu(view, canControl)`、`lanStart(node, seed)`、`lanStep(frame, fireMask, waterMask)`、`lanBatch`、`lanState(detail)`。
掩码中左=1、右=2、跳=4；必须传完整状态，帧号必须连续。

## 不改变原版游戏速度

原始 SWF 是 AS3，640×480，25 FPS，32 个关卡。物理步长原来就是 1/26 秒，50 次求解迭代；这两个值保留。
不能因为手机屏幕是 60 Hz，就把原物理调用频率直接翻倍。

LAN 模式禁用自动 ENTER_FRAME 物理与原键盘监听，只有 `lanStep` 可推进规则。
游戏计时改用同步帧，装饰性随机构造使用同种子 LCG32。

## 分帧加载是实际踩到的坑

下载完成或注册了 ExternalInterface 回调，并不意味着目标场景的类和素材已完成注册。
在文件尚未加载到第 3 帧时调用 gotoAndStop(3)，可能被夹到第 1 帧；后来会出现平台的 `bar` 为 null。

最终先检查 `framesLoaded >= 3`，再确认 `currentFrame == 3`。
对象创建放在 Flash ENTER_FRAME 事件中执行，网页桥接只提交开始请求。12 次全新上下文冷启动验证通过。

## 影片时间轴与规则分开处理

角色表情、火焰、通关楼梯等可继续按本地时间播放。死亡与通关回调却可能进入原菜单或访问已被销毁的父对象。
通关结果交由网页房间呈现；销毁后仍运行的帧脚本加父对象检查。0.3.0 的死亡不再结束整关：只重建死亡角色的原版三块碰撞形状和接触状态，原角色画面回到安全点并短暂闪烁。

## 原版菜单由玩家1操作

菜单也在两端本地显示。原按钮的开始、操作说明、说明返回、关卡点击只发出意图；父页面与 Java 服务都检查房主/玩家1权限，再广播已确认的菜单页面或关卡 epoch。
玩家2的菜单关闭鼠标/键盘操作路径，服务端也拒绝其直接菜单请求；权限随座位而不是火娃/水娃颜色。

菜单使用 node=0，不推进物理、不生成输入日志。选择关卡或退出本关时切换 epoch 并重建引擎，旧关卡输入被拒绝。进入游戏后，即使键盘焦点留在 Ruffle iframe，按键仍交给父页面统一管理。
LAN 保持 32 关可选；外部广告、联网积分等按钮不进入合作菜单。

## 每个角色自己的安全检查点

物理步进后分别检查角色竖直速度、静态地形支撑、身体空间与附近危险传感器。左右脚和中心均有地形支持、远离对应危险并连续稳定 6 帧才记录；角色免疫的火/水仍按原属性处理。移动平台不作为独立稳定支撑，悬边和障碍中的点不记录。

每人保留出生点与最近 23 个有效落脚点。死亡时重新验证历史候选，先取最近仍能安全站立的位置，必要时退回更早或出生点；不回滚宝石和机关。只销毁并按原参数重建该角色刚体，清除其接触、出口/死亡和跳跃状态，伙伴继续运行。复活后的持键锁直到该玩家输入回到零才解除。

历史位置/帧、稳定帧计数、复活次数和释放锁都进入同步摘要；因此重连或失步恢复按同一确认输入回放时，也会在相同帧复活。测试用真实关卡路线触发两种角色死亡，并验证实际红宝石保留、伙伴不归位、持键不连续死亡及另一独立实例重放一致。

## 日志与失步恢复

房间以 25 Hz 记录 `[frame, fireMask, waterMask]`。快照带最近 10 帧；错过更多时经有界接口每次取最多 250 帧。
客户端没有输入记录时不猜规则。重连或摘要不一致时，用本关、种子与完整确认记录重建。

每 10 帧报告摘要，恢复代次和关卡 epoch 拒绝旧连接数据。连续超过 3 次不一致时暂停并提示重开。
摘要覆盖刚体位置/速度/形状数量、宝石、死亡、出口帧等，可发现常见失步；有限摘要不是对整个内部状态的数学证明。

输入还带递增序号。按键 350 ms 不刷新则归零；失焦、后台、暂停清空输入。
这避免了「长按方向、同时跳跃、丢失松键后持续走」的旧键盘桥接问题。

## 保留资源时不要重新序列化整部电影

FFDec 用于编译修改后的 DoABC。0.2.0 仅替换该字节码标签，另外 990 个标签逐字节相同。0.3.0 恢复菜单时还修复原文件三个 DefineButton2 的错误 ID：0 → 381/384/388，它们分别由紧随其后的 DefineButtonSound 引用证明对应关系。按钮记录和美术数据不改；除此以外的 987 个非字节码标签逐字节相同。
编译器对其他标签的重序列化不进入最终文件。原始文件另行保留，匹配 SHA256 后才应用本 profile；`preservation.json` 明确区分按钮 ID 修复和未改动标签，不再声称所有非代码字节相同。

## 下一款游戏可复用什么

可复用：Android/WebView 容器、局域网 HTTP/WebSocket、二维码、角色输入、日志、摘要、回放与标签验证。
需要重做：根类、关卡构造、逻辑更新、随机数/时钟隔离、决定胜负的状态、动画帧脚本边界和样例测试。
AS2、依赖外部服务、用时间轴直接驱动碰撞的游戏不能直接套用此 AS3 profile。

先做两个独立实例的同帧一致性，再接房间网络；对目标手机做 ARM/WebView、长时、Wi-Fi 抖动与真实触控延迟测试。
报告里区分 ping、按键到状态、画面显示，以及软件录制与手机实拍，避免用其中一种代替另一种。
